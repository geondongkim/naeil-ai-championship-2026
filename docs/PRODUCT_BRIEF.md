# NAEIL clean-room product brief

- Product: **NAEIL (New AI Employment & Industry Link)**
- Tagline: **현장의 AI와 청년의 내일을 잇다**
- Submission: Wanted AI Championship 2026, individual entry
- Implementation rule: newly authored code and prose only

## Product definition

NAEIL is one field-data operations product that connects manufacturing and
small-business Physical AI data needs with trained, auditable youth career paths.
It demonstrates request, five-gate readiness, collection, AI-assisted quality
review, independent human review, rights-aware dataset publication, career
evidence, and failure-to-recollection linkage.

## Problem

Physical AI needs contextual field data, but small sites lack a shared operating
system for collection scope, consent, safety, quality, rights, and revision.
Meanwhile automation changes entry-level work while new field-context, data
quality, rights, deployment, and recollection roles remain poorly defined and
hard to prove as experience.

These roles are proposed career paths, not achieved employment outcomes:

- field data coordinator
- Physical AI data operator
- data quality and safety reviewer
- data rights steward
- field deployment specialist
- recollection operator

## One product, two fields

The persistent field switch changes manufacturing and small-business content in
the same shell. The selected role changes its home view, navigation, actions,
language, and visible evidence.

Minimum roles:

- requester
- field provider
- collector
- reviewer
- operations coordinator
- field deployment specialist (manufacturing emphasis)

## Non-negotiable lifecycle

`request -> consent/scope -> training/assignment -> collection -> AI signal -> independent human review -> rights-aware dataset version -> controlled use -> incident/recollection`

Collection requires all five gates: site consent, training, safety, allowed task
scope, and compensation acknowledgement. Collection, review, dataset access, and
compensation remain separate state axes. A collector cannot approve their own
submission.

## MVP proof

1. Select a role and switch fields without leaving the product.
2. Inspect a task and complete all five readiness gates.
3. upload a representative synthetic image and receive live AI quality feedback.
4. Show that the AI cannot approve; a different reviewer approves or requests
   recollection with a reason.
5. Publish an approved item into a versioned, rights-labeled dataset.
6. Add reviewed work and training to career evidence.
7. Link a manufacturing incident to a scoped recollection task.

## Truth boundaries

Implemented claims require code and runtime evidence. Authentication, durable
storage, real payment, robot control, model training, verified users, jobs,
customers, revenue, and partnerships are out of scope unless later proven.
KAMP AI, AI Hub, and data.go.kr remain external catalog candidates until a real
deployed API call is verified.

## Data labels

- Live API
- Approved cached snapshot
- External catalog link
- Licensed reference sample
- AI-generated synthetic example

Synthetic examples must never be described as collected youth work, partner-site
data, or approved training data.
