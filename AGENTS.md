# NAEIL clean-room repository instructions

Read `docs/PRODUCT_BRIEF.md` before planning, editing, reviewing, or delegating.

- This is a new individual-submission implementation. Do not copy source code,
  screenshots, UI markup, prose, or contributor assets from AI-for-Good or any
  other repository.
- Treat manufacturing and small business as field contexts inside one product.
- The selected role must change navigation, start view, allowed actions, and
  wording. A client-side role selector is a prototype UX filter, not security.
- Preserve the five collection gates: site consent, training, safety, task scope,
  and compensation acknowledgement.
- The collector cannot approve their own work. AI is an assistive signal and a
  person makes the final review decision.
- Label data as live API, approved cached snapshot, external catalog link,
  licensed reference sample, or AI-generated synthetic example.
- Do not claim authentication, durable storage, payment, robot control, training,
  employment outcomes, customers, revenue, or partnerships without evidence.
- Keep secrets, personal information, private-site details, and unclear-rights
  media out of the repository and generated deployment artifact.
- Never use `codex` in a branch name.

Run `npm run check` after product changes and verify representative desktop and
mobile role paths before deployment. Never operate the competition submission
form without explicit user confirmation.
